How it works

OAuth Runway tells a developer what it takes to create an OAuth app with a provider and get it approved, so their users can connect that app to an AI agent. Each guide is written to be followed and shared without further explanation.

What a guide answers

  • How hard it is, on a five-point scale, and why in one sentence.
  • Two separate clocks: time to a token you can test with, and time to production, where approval waits live.
  • Where approval kicks in. Most providers do not review the OAuth app itself; they gate a marketplace listing, a scope class, or a user-count cap. The guide says which.
  • The ordered steps, each tagged by who can do it: an agent, a human, or either, with the reason a human is needed (login and 2FA, legal attestation, payment, domain ownership).
  • Nuances that bite later: token lifetimes, redirect URI rules, PKCE, sandbox limits, install caps.
  • Blockers that get apps rejected or stuck, with the fix.
  • Evidence, item by item, labelled verified in docs, community reported, or uncertain, with the source.

How library guides are researched

Each library guide is written by a research agent working against a shared template. The agent reads the provider's official developer documentation first and uses community sources (forums, GitHub issues, vendor write-ups) only to label wait times and gotchas the docs do not state. Every wait, price and cap carries its evidence status. Where a number is community reported, the guide says so; where the docs are silent, it says that too. Every guide shows the date it was last checked.

What is verified and what is not

  • Verified in docs: console paths, scope classes, token lifetimes, redirect URI rules and review requirements, read from provider documentation and cross-checked against a second source where the claim matters (waits, costs, caps).
  • Not hands-on tested: the library does not claim that an OAuth app was created on a real provider account, since that needs company identities, verified domains and sometimes payment. Steps tagged Agent are what an automated agent can do once a person has signed in; this page never signs in anywhere.
  • Uncertain: anything a provider changed after the check date. Several providers (HubSpot, Salesforce, Notion, Slack) changed their app model in 2025 or 2026, so recency matters more here than usual.

How live generation works

The Generate page runs an investigation on demand. The prompt includes the closest library-guide summaries to keep difficulty and timing consistent. Gemini handles the research and draft; the page shows the search queries and resulting guide. It runs using the Gemini API key entered by the viewer:

  • The viewer supplies a Gemini API key from Google AI Studio. The page calls Gemini from the browser. Text-only generation is the default; Google Search grounding is optional because it may have a separate quota. If one model has no available quota, the page tries a lighter fallback model when possible.
  • The key is sent in a request header to Google's Gemini API rather than placed in the URL. It can be kept in session storage for the current tab only when the viewer enables that option. Free-tier data may be used by Google to improve its products, so avoid confidential or sensitive inputs. Do not publish a copy of this HTML with a real API key embedded in it.

Either way a live guide is a first draft with sources to check, not a verified one. Its banner says which mode produced it, and each one carries a confidence note saying what to double check first. When no API key is entered, the Generate page shows an example guide for Linear. This is illustrative only and is not a new live investigation.

Reading the labels

  • Verified in docs stated in the provider's official documentation at the check date.
  • Community reported from developer forums, issue trackers or vendor write-ups; the provider does not publish it.
  • Uncertain not confirmed, or likely to have changed; check the source before relying on it.
  • Agent an automated agent can do the step alone once signed in. You needs a person. Either an agent drafts, a person confirms.
